================================================================
       LINUX: ENVIRONMENT VARIABLE PLACEMENT GUIDE
================================================================


----------------------------------------------------------------
 1.  /etc/environment
     Global | Static | No scripting
----------------------------------------------------------------

 What it does : Applies to ALL users and ALL shells at login.
 Syntax       : KEY=value pairs only. No export, no logic.
 Takes effect : After full logout / login.

 EXAMPLE
 -------
   JAVA_HOME=/usr/lib/jvm/java-17
   LANG=en_US.UTF-8
   APP_ENV=production
   TZ=Asia/Kolkata

 APPLY
 -----
   # Reload without logging out (current shell only)
   $ set -a; source /etc/environment; set +a

   # Verify
   $ echo $JAVA_HOME

 USE WHEN: You need a simple, unchanging system-wide value.


----------------------------------------------------------------
 2.  /etc/profile.d/custom.sh          [RECOMMENDED]
     Global | Flexible | Supports scripting
----------------------------------------------------------------

 What it does : Every *.sh file here is sourced for all login
               shells. One file per concern -- easy to manage.
 Syntax       : Full bash -- export, conditionals, functions.
 Takes effect : Next login, or source manually (see below).

 EXAMPLE  (/etc/profile.d/myapp.sh)
 -----------------------------------
   export APP_HOME=/opt/myapp
   export PATH="$APP_HOME/bin:$PATH"

   if [ "$(hostname)" = "prod-server" ]; then
       export DB_HOST=db.prod.internal
   else
       export DB_HOST=db.dev.internal
   fi

 APPLY
 -----
   # Make executable (first time only)
   $ sudo chmod +x /etc/profile.d/myapp.sh

   # Reload current shell immediately
   $ source /etc/profile.d/myapp.sh

   # Or reload all profile.d scripts at once
   $ source /etc/profile

   # Verify
   $ echo $APP_HOME
   $ echo $DB_HOST

 USE WHEN: You need system-wide vars with logic or conditions.


----------------------------------------------------------------
 3.  ~/.bash_profile
     User-specific | Login shells only
----------------------------------------------------------------

 What it does : Sourced only for the current user on login.
               Does NOT affect other users or system services.
 Syntax       : Full bash -- export, conditionals, aliases.
 Takes effect : Next login, or source manually (see below).

 EXAMPLE  (~/.bash_profile)
 ---------------------------
   export GOPATH="$HOME/go"
   export PATH="$GOPATH/bin:$PATH"
   export EDITOR=vim

 APPLY
 -----
   # Reload current shell immediately (no logout needed)
   $ source ~/.bash_profile

   # Verify
   $ echo $GOPATH
   $ echo $PATH

 USE WHEN: Personal overrides that should not affect others.


================================================================
 QUICK DECISION GUIDE
================================================================

  Scenario                              Use
  ------------------------------------  ------------------------
  Global + simple constant?             /etc/environment
  Global + needs logic/conditions?      /etc/profile.d/custom.sh
  User-specific override?               ~/.bash_profile


================================================================
 UNIVERSAL: VERIFY ANY VARIABLE
================================================================

  # Check a single variable
  $ printenv MY_VAR

  # List all environment variables
  $ printenv

  # Check what a login shell sees
  $ bash -l -c 'echo $MY_VAR'

  # Simulate what cron / systemd services see (clean env)
  $ env -i bash --login -c 'echo $MY_VAR'


================================================================
 WARNING: DO NOT USE .bashrc FOR PERSISTENT VARIABLES
================================================================

  .bashrc is sourced only by interactive non-login shells.
  Cron jobs, systemd services, and SSH commands will NOT
  inherit variables defined there.

  WRONG   -> in ~/.bashrc   : export DB_PASS=secret
  CORRECT -> in profile.d/  : export DB_PASS=secret
